vitaFTPShell — SERVER, direction A states

Direction A is chosen: a status panel with the address and controls, plus a dedicated warning panel and a client panel. This sheet develops the server states. The no-network error uses the same error line as the bind failure and is noted below.

960 × 544 status 552 × 352 warning 360 × 200 client 360 × 140 type 5×7 face, 1.5 / 2 / 3 / 5 px
1OFF at launch

The launch state. The warning is visible before the first start; the start slab is focused; the address is dim because nothing is listening.

2Starting

The listener is binding. A cancel slab replaces start; the address stays dim until the bind completes.

3ON, no client

Running with no client. The stop slab is focused, the address is live, and the client panel says no client.

4ON, client browsing

One client browsing /UX0:/DATA/. The client panel names the operation and path; the dock counts one client.

5ON, client transferring

One client uploading FILE.VPK. The client panel carries the operation, path, and bytes; the dock becomes the transfer bar. Stopping now opens CONFIRM.

6Bind failure

A bind failure. The port is focused for editing, the error names the port, and the server stays OFF. No-network uses the same line with NO NETWORK - CONNECT TO WI-FI.

Settled in this pass: the status panel with the big state, address, port, clients, access, and the start/stop/cancel slab; the warning panel carries the risk and the launch/stop lifecycle; the client panel carries identity, operation, path, and bytes; the dock shows the server status or the active server transfer; the error line sits under the address, and the port takes focus on a bind failure.

Still open: the exact no-network copy; what the UI shows when a second client is refused (the PC gets a busy reply, the Vita still shows one client); the port-entry overlay; and the stop-during-write confirmation, which belongs to CONFIRM.

Not shown: CONFIRM, text entry, the second client’s busy reply, and the session log.
