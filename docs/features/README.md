# Feature documents

A feature document is for behavior added after v1. It is not an implementation
plan and it does not replace the v1 requirements.

## When to add one

Add a dated document here when a feature has a problem, users, and scope worth
preserving, or when a decision would otherwise live only in a conversation.

## Naming

`YYYY-MM-DD-<topic>.md`

## Suggested shape

- **Problem** — who is stuck, and what it costs.
- **Users** — the primary user for this feature, and any secondary pull.
- **Proposed behavior** — what changes, in plain words.
- **Requirements** — numbered, testable, with the same R-ID discipline as the v1
  plan.
- **Scope** — what is deferred and what is outside the product.
- **Decisions** — link to `../DECISIONS.md` entries when one is made.
- **Plan** — link to the implementation plan once one exists.

Use `ce-brainstorm` for new behavior. Use `ce-plan` for the implementation plan.
Link the result here; do not copy the whole plan.
